# 能力评价方法 v1

本库评价“某个版本的方法在某类任务、某种环境下能否产生有证据的帮助”。不评价模型人格，不将文档长度、调用次数或自我评价合并成一个能力总分。首次导入的内容质量分析是文档审查，历史使用是观察数据；二者分栏。

## 一、先确定统计单位

| 单位 | 定义 | 不能替代什么 |
|---|---|---|
| 物理文件 | 某个实际路径的 SKILL.md | 不等于一个独立能力 |
| 逻辑技能 | namespace + name，同名不同提供者保留 | 不把同名 PDF 技能自动合并 |
| 技能版本 | 正文内容 SHA256 与路径/发布版本 | 今天的文本不能代表过去读到的版本 |
| 使用片段 episode | 同会话、同轮、同技能的去重实际调用 | 不用读取10次冒充10个成功任务 |
| 工作目录 | 日志记录的 cwd | 不一定是独立项目，多个 worktree 可能同仓库 |
| 项目组 | 有仓库身份或明确项目证据的归一组 | 无证据时不凭名字归并 |
| 结果审查案例 | 技能 → 行为改变 → 可观察产物/验证 | 工具exit 0、最终答复不是完整因果证明 |

所有统计附覆盖根目录、时间窗口、去重版本、扫描失败、源文件冻结信息和缺失值。未观察到使用表示“当前证据未见”，不表示从未使用。历史日志范围不完整时不给全生命周期使用率。

## 二、评价矩阵

| 维度 | 可复算指标 / 问题 | 证据与计算 | 解读与决策 |
|---|---|---|---|
| 发现与可用性 | 当前宿主可发现、显式禁用、仅缓存、依赖缺失 | 本地目录、宿主配置、当前目录清单；写清采集日期 | 磁盘存在≠可调用；默认排除已禁用/备份 |
| 需求适配 | 任务的触发条件、输入、产物和约束是否满足 | 场景节点与技能正文，含不适用条件 | 先做适用性门槛，再看历史热度 |
| 观察频次 | read / executed / declared 各自的去重片段数 | 解析允许字段中的真实调用，排除系统目录和嵌套历史 | declared不与实际使用相加；高频不证明高效 |
| 使用广度 | 独立会话数、工作目录数、经确认项目组数 | cwd与项目映射及归一证据 | 可比较复用范围，不能冒充独立用户数 |
| 时间分布 | 首次/末次、近30/90天，最近窗口覆盖程度 | 日志时间；不以文件mtime代替使用时间 | 新技能的低频与旧技能休眠分开 |
| 已证实帮助 | verified_help案例 / 已人工审查结果案例 | 实际指导影响后续操作且有产物/测试来源 | 未审查样本不放进成功率分母；样本小直接列案例 |
| 有效性覆盖 | 已审查案例数 / 观察使用片段数 | 同一统计单位，同一冻结窗口 | 低覆盖时结论是效果未建立，不能评“差” |
| 关键贡献 | 是否解除阻塞、纠正主假设、避免返工、完成不可替代步骤 | 具体前后行为、阻塞记录、结果与替代方案 | 没有反事实比较，只能称重要贡献或潜在关键，不能称唯一原因 |
| 失败与负迁移 | 已证实误导、环境不兼容、重试仍失败 | 错误、实际后果、纠正链；保留版本 | 仅给失败范围内的限制，不全局封杀技能 |
| 验证强度 | 描述、代码、单测、隔离集成、回放、发布、目标接受、真实结果 | 案例自己的验证层与输入身份 | 更高层不自动消除低层缺陷；发布≠设备成功 |
| 证据质量 | 直接证据/转述、定位完整性、版本一致性、可重放程度 | 文件/行、hash、call_id、来源与截止范围 | 多个AI重复同一来源不算独立佐证 |
| 认知成本 | 入口字符数、按需引用、任务所需实际读取量 | 文档规模只是proxy，实测token需可得账单 | 长文不自动差；按需读取能降低负担 |
| 执行成本 | 可测耗时、工具数、外部费用、重复检索 | 仅记录实际有数据的成本和单位 | 无数据写null；不估造节省时间 |
| 架构与解耦 | 业务规则、证据、索引、UI、宿主入口能否独立替换 | 入口依赖、脚本接口、配置与正文 | 隐式改全局配置、强绑工具品牌降低迁移性 |
| 维护性 | 链接失效、脚本测试、依赖版本、变更/回退办法 | 实际检查或文档声明分开 | 有tests文件不等于测试通过 |
| 可迁移性 | 操作系统、宿主、账号、项目路径、模型限制 | 明示依赖与一次异环境验证 | 没有跨环境测试只称设计可迁移 |
| 冲突与冗余 | 同名、重复内容、互斥规则、适用边界重叠 | 内容hash、来源版本、差异审查 | 重叠有时提供替代实现，先路由不先删除 |
| 风险与恢复 | 数据写入/发布/硬件/权限/不可逆步骤及恢复路径 | 技能正文与具体任务授权 | 图谱提供知识不授予新权限，不重放历史命令 |
| 新鲜度 | 最后验证时间、环境指纹、review_after、依赖变动 | 内容hash变更、客户端/SDK版本、失效证据 | 到期表示需复查，不自动判假；先隔离过时断言 |
| 组合价值 | 能否和其他能力串成完成任务的最小链 | 依赖边与每一步输入输出契约 | 少步骤不必更好；避免同类技能全部加载 |
| 知识收益 | 获得何种事实、改变哪次操作、带来何种结果 | acquisition → decision → action → result链 | 只有阅读没有行为影响记unproven，不臆测隐藏思考 |
| 检索质量 | 正确候选召回、首选是否合适、负例是否避开 | 人工标注场景测试；记录候选与实际选择 | 排序分只用于找候选，绝不能显示成效果评分 |
| 写回质量 | 新证据比例、重复/冲突/未验证断言比例 | 引用、父知识ID、验证事件、版本历史 | 不能让生成内容循环引用自证正确 |

## 三、评级方式

保留多维卡片，不给“屎山分数”式伪精确加权平均。文档结构可用 `clear / partial / unclear`，证据用 `observed / reviewed / unknown`，适用性用 `fit / conditional / out_of_scope`。空值统一表示未知，而不是0分。

效果至少分 `verified_help / mixed / failure / unknown`。verified_help意味着有明确范围的案例帮助，不意味着对该技能的普遍有效性认证。批量启发式解析不可以直接赋此值。用户肯定可作为反馈来源，不能替代实测产物。多个同源副本去重后才统计。

频率用原始计数并给分位解释（仅在同一观察窗口内），不要先武断划“高/低”。案例数不足、项目集中时不比较技能胜负。确需成功率时同时展示 n/N、缺失数量与场景构成，不把不同任务混算。

还必须公开**审查抽样策略**：优先挑有产物、成功或高风险案例会产生选择偏差。首次少量人工案例只证明这些案例，不用“已审案例帮助比例”外推所有历史。实际任务中有多少次适用机会、漏用了多少次、误用了多少次也应积累；机会分母缺失时不能把低频称为采用率低。

## 四、选择能力的顺序

1. 匹配用户目标、产物、输入、可用工具和本次授权。
2. 排除当前不可用、冲突、退役以及前置条件不满足的候选。
3. 读取最多几个候选的适用边界与关键步骤。相似项目只作为经验来源，确认版本、环境和物理边界。
4. 优先有同场景帮助证据的方法；若无证据，以最小可验证试验补足，而不是编造置信度。
5. 使用后记录行为变化、实际验证和未解决问题；已有知识不足时组合procedure节点，不必立刻新建skill文件。

全文检索只是候选生成器；模型仍要执行1–4的判断。当前实现不声称具有语义嵌入检索或自动任务规划。

## 五、需要进一步积累的数据

首次盘点通常无法从历史日志恢复所有成本、用户满意度、skill版本和负例。这些字段保留null。以后的使用片段记录任务类型、输入身份、选择原因、实际指令/动作、结果证据、验证层、是否改变决策和是否有更简单方案，才能逐步回答“到底哪个好用”。

版本归因记录 `historical_version_known`，路径匹配只说明对应当前目录，不能绑定今天的SHA。维护成本包括检索、记账、复核本身；若这些工作没有改变决策，应该减少维护粒度。组合方法还须验证A输出是否满足B输入，含中间状态与权限，单步都有效不保证组合有效。

上游知识被纠正后，沿 `derived_from / depends_on / supersedes` 查找依赖，逐项判断哪些条目需要复核。当前运行时提供关联展开，**不自动证明下游仍有效，也不自动传播真/假状态**；结构health通过与语义正确性分开。后续可测纠错触达率与未复核依赖数，首次没有数据不生成分数。
